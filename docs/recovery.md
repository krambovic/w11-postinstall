# Восстановление

Реестр восстанавливается по сохранённому **исходному значению**, а не универсальным «значениям по умолчанию». Хранятся тип, значение и факт существования. Если значение отсутствовало, при откате оно удаляется. Созданный пустой конечный ключ может быть удалён без рекурсивного удаления общих веток.

Откат работает в обратном порядке. Если текущее значение отличается и от ожидаемого после Apply, и от исходного, фиксируется Conflict: чужое последующее изменение остаётся на месте. Восстановление требует исходных SID, базовой сборки и версии кода/каталога. Хранить копию использованного релиза вместе с журналом.

```powershell
.\Start.ps1 -Mode Restore -RunId <id> -WhatIf
.\Start.ps1 -Mode Restore -RunId <id>
```

Журнал пишет intent перед действием и результат после. После прерывания запись Applying означает неизвестный исход; для реестра Restore проверит состояние. Для установщиков и удалённых приложений требуется ручная проверка. Не удалять журнал до проверки результата восстановления.

## Приложения

- Удалённый Appx: установить заново из Microsoft Store или официального источника. Автоматического восстановления пакета и пользовательских данных нет.
- Установленная программа: удалить через Windows или соответствующий менеджер после проверки. Скрипт не запускает массовое удаление при Restore.
- Provisioned-пакеты и профили других пользователей в preview не меняются.
- При повреждении системы использовать собственный заранее подготовленный образ/средства восстановления Windows. Этот инструмент их не заменяет.

В preview нет автоматической точки восстановления или backup-образа. Безопасность проверок обеспечена тем, что на машине разработки системные операции вообще не запускались. До реальных испытаний делать снимок отдельной VM.
