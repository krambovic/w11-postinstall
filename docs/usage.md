# Использование CLI

## Мастер настройки

Скачай только `W11PostInstall.ps1` из релиза. Он работает отдельно от исходников. В исходниках те же команды принимает `Start.ps1`.

```powershell
.\W11PostInstall.ps1 -WhatIf
.\W11PostInstall.ps1
```

Мастер выбирает профили и пакеты, показывает общий план и после одного подтверждения применяет его. Balanced включает пользовательские твики и удаление Get Started и Feedback Hub, если они установлены. Для программ доступны базовый пакет, базовый пакет с Telegram и Discord, пропуск или выбор отдельных ID. Мастер спрашивает менеджер только если установлены оба и выбраны программы. При отсутствии Chocolatey он использует WinGet, если тот установлен. Если менеджеров нет, установка программ недоступна; менеджеры автоматически не загружаются.

`-WhatIf` без вопросов показывает план с параметрами по умолчанию или переданными явно. `-NonInteractive` применяет план без вопросов при наличии `-AllowUnverified`, `-AcceptAgreements` для установки и `-AcceptRisk` для удаления Appx. Для установки в этом режиме консоль должна быть уже повышена. В интерактивном мастере после подтверждения при необходимости появится UAC; другая учётная запись не может применить план.

## Ручное меню

`-Mode Menu` открывает подробный выбор действий, программ и менеджера.

Выбор действий дополняет профиль. Чтобы собрать только собственный набор, выбрать `Custom`. У программ ввод ID переключает выбор: повторный ввод убирает приложение. Поиск принимает часть имени, категорию и теги `modern`, `heavy`, `artcraft`. Тег `modern` — подборка проекта, не рейтинг популярности. Тег `heavy` качественный: точный объём установки не измерен.

Выбор программы сам по себе ничего не устанавливает. Для ручных позиций план показывает официальный сайт; скрипт не открывает браузер и не скачивает дистрибутив.

## Планы

```powershell
.\Start.ps1 -Mode Plan -Profile Balanced -OutFile .\plan.json
.\Start.ps1 -Mode Plan -Profile Custom -Actions explorer.extensions,ui.dark-apps -Apps firefox,7zip -Provider Choco
.\Start.ps1 -Mode Apply -PlanFile .\plan.json -WhatIf
```

План фиксирует SID, выпуск/сборку/UBR, редакцию, архитектуру, исходное состояние, выбранный менеджер и SHA-256 кода/каталогов. Перед применением скрипт сверяет их заново. Это защита от случайного изменения и устаревания, а не цифровая подпись доверенного издателя.

Изменился пользователь, Windows, код, каталог или состояние выбранного пункта — создать новый план. Параметры профиля/менеджера нельзя подмешать к сохранённому `PlanFile`.

Собственный JSON-профиль:

```json
{
  "SchemaVersion": 1,
  "Name": "My setup",
  "Provider": "Choco",
  "Actions": ["explorer.extensions", "privacy.advertising"],
  "Apps": ["firefox", "7zip", "localsend"]
}
```

```powershell
.\Start.ps1 -Mode Plan -ProfileFile .\my-profile.json -OutFile .\plan.json
```

Неизвестные поля и ID отклоняются. В JSON нет произвольных команд и сценариев. Явный параметр `Provider` при создании плана переопределяет менеджер профиля.

## Реальное применение — только на тестовой системе

Preview не прошёл тесты на реальных сборках. Следующие команды **действительно меняют Windows**; они приведены для будущей проверки в отдельной VM:

```powershell
.\Start.ps1 -Mode Apply -PlanFile .\plan.json -AllowUnverified -AcceptAgreements
# Для плана с удалением Appx дополнительно требуется -AcceptRisk:
.\Start.ps1 -Mode Apply -PlanFile .\plan.json -AllowUnverified -AcceptAgreements -AcceptRisk
```

`AllowUnverified` не разрешает Defender Remove, неизвестные сборки и неподдерживаемые архитектуры. `AcceptAgreements` — явное согласие с лицензиями выбранных пакетов/источников. `AcceptRisk` — согласие на возможную потерю данных выбранных Appx. Флаги независимы.

Установка приложений в preview требует повышенной консоли. Пользовательские твики работают без неё. План создавать и применять от одного пользователя: UAC с учётными данными другого администратора изменит SID и будет отклонён. Автоматического повышения/переноса пользовательского контекста пока нет.

Chocolatey нужен версии 2+, WinGet — 1.6+. Скрипт вызывает только точные ID из каталога, с фиксированным источником и без отключения проверки хеша. Chocolatey использует community-пакеты, чьи сценарии могут исполнять код установщиков с текущими правами. Проверять выбранный пакет необходимо независимо от метки recommended.

Предварительный план не обращается к удалённым пакетным источникам. Он определяет уже установленное через реестр удаления программ; это не охватывает все portable/Store-приложения. При реальном Apply дополнительно опрашивается выбранный менеджер. При неясном результате диагностики установка блокируется, а не повторяется вслепую.

Установки выполняются последовательно. После ошибки или требования перезагрузки выполнение прекращается; остальные пункты получают Skipped. Скрипт не перезагружает ПК. `RebootRequired` означает, что установка/её эффект ещё не подтверждены; после самостоятельной перезагрузки создать свежий план. Автоматического resume в этой версии нет.

При таймауте завершается процесс менеджера; дочерний установщик может продолжать работу. Проверить состояние вручную до нового запуска. Сырые коды завершения сохраняются; полные логи менеджеров остаются в их штатных каталогах, без копирования в репозиторий.

## Журнал

По умолчанию: `%LOCALAPPDATA%\W11PostInstall\<RunId>.json`. Выбран локальный каталог пользователя для preview; общий ProgramData и много пользовательский broker из полного плана отложены.

Каталог создаётся с ACL для текущего SID, SYSTEM и Administrators. `DataRoot` должен быть новым выделенным каталогом или ранее созданным WPI; скрипт отказывается менять права произвольного существующего каталога. Блокировка не даёт двум экземплярам одновременно применять изменения в одном DataRoot. Для защиты от разных процессов Windows это не глобальная транзакция.

```powershell
.\Start.ps1 -Mode Report -RunId <32-символьный-id>
.\Start.ps1 -Mode Restore -RunId <32-символьный-id> -WhatIf
.\Start.ps1 -Mode Restore -RunId <32-символьный-id>
```

Экспорт отчёта через `-OutFile` содержит локальное состояние и SID; перед публикацией удалить личные сведения. Автоматической обезличивающей обработки в preview нет.

## Exit codes

| Код | Значение |
|---:|---|
| 0 | Операции выполнены/уже соответствуют; для WhatIf только просмотр |
| 1 | Ошибка входных данных, предварительной проверки или окружения |
| 2 | Частичный результат, ошибка операции или ручные/недоступные пункты; неполное восстановление |
| 3 | Отмена подтверждения |
| 3010 | Требуется перезагрузка; завершённость установки ещё не подтверждена |

Это коды самого проекта. NativeExitCode в журнале — исходный код конкретного менеджера.
