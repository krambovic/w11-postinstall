# W11 PostInstall — план проекта на утверждение

Статус: план утверждён; реализуется 0.1.0-preview. Фактическое состояние и отложенные пункты — в docs/roadmap.md.
Дата: 11 ноября 2026 года. Рабочее название репозитория: `w11-postinstall`.

### Утверждённые уточнения

- Реализация и публичный репозиторий `krambovic/w11-postinstall` разрешены пользователем.
- На машине пользователя ничего не скачивать и не устанавливать; проверять только синтаксис и имитации. Не применять системные операции, не создавать VM/образы и не загружать тестовые зависимости.
- Предлагать Chocolatey / WinGet; **Chocolatey (recommended)** первым и по умолчанию. Разделы первоначального плана с WinGet как единственным провайдером расширены этим требованием.
- Расширить каталог, включая современные программы и ArtCraft: https://github.com/storytold/artcraft и официальную линейку https://getartcraft.com/.
- Полная проверка совместимости и Defender Remover отложены до отдельной изолированной тестовой среды. Называть исходный preview стабильной реализацией всего плана нельзя.

## 1. Цель и результат

Открытый CLI-инструмент для настройки Windows 11 после установки: удаление ненужных приложений, оптимизация под выбранный сценарий, настройка интерфейса и приватности, установка программ, отдельный модуль Windows Defender Remover.

Принцип оптимизации: уменьшать ненужную фоновую активность и расход диска, сохраняя выбранные пользователем функции. Ускорение подтверждать измерениями; не обещать фиксированную прибавку FPS или производительности на любом ПК.

Результат v1.0: скачиваемый ZIP с PowerShell-скриптом, интерактивным меню RU/EN, JSON-профилями, каталогами действий и программ, журналом, восстановлением поддерживаемых настроек, тестами, инструкцией и матрицей фактически проверенной совместимости.

## 2. Технологии и запуск

- Базовая среда: встроенный Windows PowerShell 5.1. Установка Python, Node.js и PowerShell 7 не требуется.
- Точка входа: `Start.ps1`; вспомогательный `Start.cmd` для удобного запуска и корректной передачи кода завершения.
- Нативные PowerShell-модули и средства Windows; WinGet для установки программ.
- PowerShell 7 — дополнительная среда после отдельной проверки совместимости; Windows-специфичные операции при необходимости выполняются адаптером через 5.1.
- UTF-8 с BOM для файлов PowerShell 5.1, содержащих кириллицу. JSON — UTF-8. Без зависимости от Windows Terminal и ANSI-цветов.
- Локальный запуск из распакованного релиза. Не делать выполнение скачанного текста через `iex` основным способом запуска.
- Не изменять постоянную ExecutionPolicy; учитывать ограничения Group Policy и выдавать понятную диагностику.
- Повышение прав только для выбранных операций. Сохранять SID исходного пользователя, чтобы настройки HKCU и установка user-приложений не попали в профиль другого администратора при UAC.
- Для разработки: Pester 5 и PSScriptAnalyzer с закреплёнными версиями; пользователям эти зависимости не нужны.

## 3. Совместимость

Целевой диапазон: Windows 11 21H2–26H2 включительно. Поддержку скриптом отделять от срока поддержки ОС Microsoft.

| Выпуск | Базовая сборка | План проверки |
|---|---:|---|
| 21H2 | 22000 | Отдельная legacy-VM |
| 22H2 | 22621 | Отдельная legacy-VM |
| 23H2 | 22631 | Отдельная VM |
| 24H2 | 26100 | Отдельная VM |
| 25H2 | 26200 | Отдельная VM |
| 26H1 | 28000 | Отдельная ветка совместимости и проверка на подходящем устройстве |
| 26H2 | 26300 | Отдельная VM |

Приоритет v1.0: x64, Home и Pro. Enterprise/Education проверяются отдельно, с учётом политик. ARM64, LTSC, N и S mode обнаруживаются явно; поддержка конкретных операций объявляется только после соответствующих тестов. Для 26H1 учитывается отдельная платформа: простой диапазон номеров сборок не подходит.

Определять версию, Build/UBR, редакцию, архитектуру, язык, тип устройства, питание от батареи, доступность модулей и пакетов. Для каждого действия хранить ограничения и проверку возможностей. Нельзя считать операцию поддерживаемой только потому, что ключ реестра удалось создать.

Неизвестная или непроверенная сборка: диагностика и просмотр плана доступны; действия без подтверждённой применимости блокируются. Для устаревшей ОС показывать статус поддержки Microsoft, не выдавая его за отказ совместимости самого скрипта.

## 4. CLI и основной сценарий

Главное меню:

1. Диагностика системы.
2. Готовые профили и собственный профиль.
3. Debloating.
4. Tweaks: интерфейс, приватность, производительность.
5. Установка программ.
6. Defender: состояние, настройки, экспериментальный Remover.
7. Просмотр и применение плана.
8. История, восстановление и отчёт.

Последовательность: диагностика → выбор → проверка зависимостей/конфликтов → предварительный план → резервирование → применение → проверка фактического результата → отчёт и предложение перезагрузки.

Для каждого пункта показывать описание, ожидаемый эффект, побочные последствия, уровень риска, область действия, способ восстановления и необходимость перезагрузки. Меню работает с обычным вводом цифр, без обязательного мышиного интерфейса.

Предлагаемый контракт CLI, а не уже реализованные команды:

```powershell
.\Start.ps1 -Mode Diagnose
.\Start.ps1 -Mode Plan -Profile Balanced -OutFile .\plan.json
.\Start.ps1 -Mode Apply -PlanFile .\plan.json
.\Start.ps1 -Mode Apply -ProfileFile .\my-profile.json -WhatIf
.\Start.ps1 -Mode Apply -ProfileFile .\my-profile.json -NonInteractive -AcceptAgreements
.\Start.ps1 -Mode Restore -RunId <id>
.\Start.ps1 -Mode Report -RunId <id>
```

`-WhatIf` не изменяет реестр, пакеты, службы и задачи; разрешённая запись самого плана/отчёта оговаривается отдельно. `-NonInteractive` не означает согласия с лицензиями и опасными операциями. Для последних нужны явно выбранные действия и отдельный флаг принятия риска. Утверждённый план содержит хеш профиля и каталога; перед применением исходное состояние проверяется повторно, при существенном расхождении требуется новый план.

Коды завершения проекта: 0 — успех; 1 — ошибка предварительной проверки; 2 — частичный результат; 3 — отмена; 4 — ошибка применения/восстановления; 3010 — успех с необходимостью перезагрузки. Сырые коды WinGet и установщиков сохраняются отдельно.

## 5. Профили

| Профиль | Содержание |
|---|---|
| Balanced | Удаление явно необязательных приложений, рекомендации/реклама, удобство интерфейса; предлагается первым |
| Minimal | Более широкий debloat; необязательные интеграции и фоновые приложения выбираются явно |
| Gaming | Сохранение нужного Xbox/Game Pass-стека, настройка захвата и игрового режима по возможностям системы |
| Privacy | Минимизация разрешённой редакцией диагностики, рекламы, рекомендаций и персонализации |
| Laptop | Настройки с приоритетом автономности, сохранение сна и функций питания |
| Custom | Собственный набор с экспортом и повторным применением |

Профиль — данные с перечнем действий и параметров. Объединение профилей возможно только после разрешения конфликтов. Defender Remover не входит автоматически ни в один профиль.

## 6. Debloating

- Инвентаризация Appx/MSIX, provisioned-пакетов, обычных приложений и необязательных компонентов.
- Удаление по точным идентификаторам и проверенному каталогу, без широких масок, затрагивающих системные зависимости.
- Три разных области: текущий пользователь; существующие пользователи; provisioned-пакеты для новых профилей. Не выдавать одну область за другую.
- Категории кандидатов: рекламные приложения, новости/погода, Solitaire, Feedback Hub, необязательные Xbox-приложения, Clipchamp, Teams consumer, Copilot и другие реально присутствующие пакеты.
- OneDrive — отдельное действие: обнаружение синхронизации и перенаправленных папок, объяснение последствий, без удаления пользовательских облачных файлов.
- Store, App Installer/WinGet, WebView2, оболочка и библиотеки зависимостей защищены от массового удаления.
- Edge, поиск и Widgets — отдельные действия с проверкой способа, версии, региона и зависимостей. Недоступный поддерживаемый способ удаления помечается как ограничение.
- Опциональное удаление компонентов: печать, Hyper-V, WSL, Sandbox и т. п. только по отдельному выбору с отображением зависимостей.
- Возврат приложения различается: повторная регистрация сохранившегося пакета, установка из Store/WinGet либо исходного дистрибутива. Данные удалённых приложений автоматически не восстанавливаются.

## 7. Tweaks

### Интерфейс

Расширения файлов и скрытые файлы; тема; выравнивание панели задач; доступные переключатели поиска, Widgets и Task View; рекомендации и уведомления; параметры Проводника; анимации и прозрачность; необязательное классическое контекстное меню только для проверенных сборок.

### Приватность

Рекламный идентификатор, персонализированные предложения, диагностические данные в пределах возможностей редакции, разрешения приложений, фоновая активность и облачные интеграции. Показывать, какие настройки реально применимы. Не обещать «нулевую телеметрию».

### Производительность

Аудит автозагрузки, фоновых приложений, служб и задач. Для изменений — точный каталог зависимостей, без массового отключения. Индексирование поиска и захват игр — выбор пользователя. Планы питания зависят от ноутбука/десктопа и поддерживаемых режимов. Временные файлы очищаются с понятной областью, без Downloads и личных каталогов по умолчанию.

VBS/Memory Integrity и другие параметры с компромиссом между защитой и производительностью — отдельные расширенные действия после проверки поддержки, без включения в обычные профили. Отключение файла подкачки, случайные TCP/HPET/BCD-твики и «очистители RAM» в стандартный каталог не входят: каждое добавление требует обоснования и проверки.

### Удобство и обновления

Часы активности, доступные параметры Delivery Optimization, настройка уведомлений и предложение обновления системы. Windows Update, Firewall, UAC, SmartScreen, восстановление и критические службы не отключаются попутно с debloat. Настройки браузера по умолчанию открываются штатным способом; защищённые пользовательские ассоциации не подменяются обещанием «тихого» назначения.

## 8. Windows Defender Remover

Это явно запрошенная функция, для которой необходим отдельный этап исследования и проверки по сборкам.

Модуль разделяется на три режима:

1. **Status**: состояние Antivirus, Tamper Protection, платформы Defender, стороннего AV и организационного управления.
2. **Configure**: доступные штатные настройки и проверка поведения при стороннем антивирусе; это не называется удалением.
3. **Remove / Experimental**: фактическое удаление только для конкретных сочетаний Windows и платформы Defender, для которых найден и воспроизведён рабочий метод.

До реализации Remove нужно проверить метод в VM: удаление, перезагрузка, обновление Windows, состояние Security Center, работоспособность Store/WinGet, отсутствие нарушений обслуживания системы, восстановление из образа. Зависимости стороннего remover, если он понадобится, проходят проверку исходников, лицензии, закрепление версии и контроль целостности; удалённый скрипт из ветки latest не исполняется.

Tamper Protection может блокировать изменение даже при внешне успешной команде. Скрипт проверяет фактическое состояние и сообщает `Blocked`, а не `Success`. Организационные политики не переопределяются.

Для Remove нужны отдельный выбор, явное принятие риска и подтверждённая пользователем резервная копия образа/снимок VM. Проверка файла журнала или создание точки восстановления не доказывает наличие пригодного образа. Полный автоматический откат удаления заранее не обещается: может потребоваться восстановление образа или ремонтная установка.

Если рабочий метод не подтверждён на конкретной сборке, Remove остаётся `Unsupported` с указанной причиной. Наличие лишь меню не считается готовностью Remover. Критерий выпуска всей функции — опубликованная матрица реально проверенного удаления; обещание удаления на всех 21H2–26H2 возможно только после прохождения всей матрицы. Этот этап может потребовать пересмотра объёма после исследования.

## 9. Установка программ

Основной провайдер — WinGet. Каталог содержит точный Package ID, источник, категорию, допустимые архитектуры, scope, зависимости, параметры silent, способ обнаружения установки и дату проверки. Конкретные ID проверяются при реализации и перед релизом.

Предлагаемый набор для выбора:

| Категория | Кандидаты |
|---|---|
| Браузер | Firefox, Brave, Chrome — по умолчанию выбрать один |
| Редактор | Notepad++, Visual Studio Code — на выбор |
| Медиаплеер | VLC, mpv — на выбор |
| Архиватор | 7-Zip |
| Общение | Telegram Desktop, Discord, WhatsApp — без автоматического входа в аккаунты |
| PDF | SumatraPDF |
| Утилиты | Everything, PowerToys — необязательно |
| Офис | LibreOffice — необязательно |
| Игры | Steam — необязательно |

Это кандидаты каталога; наличие установщика, доступность по региону, silent-режим и поддержка ОС проверяются отдельно. Предлагаемый комплект Balanced: один браузер, один редактор, один плеер и 7-Zip; мессенджеры пользователь выбирает сам.

Особенности установщика:

- Проверка наличия и версии WinGet. Если отсутствует — предложить установку официального App Installer с зависимостями; при недоступности корректно пропустить блок программ.
- Установка по точному ID и источнику, проверка доступности нужных флагов в установленной версии WinGet.
- Принимать соглашения автоматически только при явно заданном согласии.
- Не отключать проверку хешей; скачиваемые напрямую официальные fallback-установщики допустимы только при наличии проверяемой целостности/подписи и отдельного адаптера.
- Существующие приложения по умолчанию пропускать; обновление — отдельная операция. Повторный запуск не переустанавливает всё.
- Последовательные установки, ограниченные повторы сетевых сбоев, таймауты, сырые коды и нормализованный результат. Не перезапускать автоматически установщик после неясного исхода.
- Silent не гарантирует отсутствие диалогов у любого стороннего установщика; такие пакеты отмечаются отдельно.
- Перезагрузка только по явному выбору. Поведение каждого установщика проверяется отдельно.
- Offline-режим: настройки и debloat работают из локального каталога, сетевые операции пропускаются с объяснением. Полный offline-репозиторий приложений не входит в v1.0.

## 10. Ядро применения и восстановления

Каждое действие имеет: `Id`, описание RU/EN, категорию, риск, scope, условия применимости, зависимости/конфликты, `Detect`, `Test`, `Apply`, `Verify`, стратегию `Undo`, признак перезагрузки и ссылки на обоснование.

Статусы: Planned, Unsupported, Blocked, AlreadyCompliant, Applied, Verified, Failed, Skipped, RebootRequired, Restored. Итоговый успех допускается после Verify; для отложенного эффекта требуется проверка после перезагрузки.

Перед изменением сохранять исходное значение, тип и наличие параметра реестра; состояние службы/задачи; параметры компонентов; список приложений. Не заменять восстановление исходного состояния сбросом к «дефолтам» Windows.

Журнал записывается до действия и после него. Применение изменений не является единой транзакцией Windows: при сбое прекращаются зависимые операции, выполненные обратимые действия можно восстановить в обратном порядке. Независимые установки программ могут продолжаться по политике профиля.

Откат учитывает более поздние запуски и внешние изменения: при несовпадении ожидаемого состояния — конфликт и явное решение, без слепого перезаписывания. Удалять при восстановлении можно лишь приложения, установленные данным запуском, после отдельного выбора; существовавшие ранее приложения не затрагиваются.

Точка восстановления создаётся, если доступна, с учётом системного ограничения частоты. Ошибка не маскируется. Для обратимых настроек остаётся собственный журнал; для необратимых действий отсутствие требуемой резервной копии блокирует выполнение.

Состояние хранится в `%ProgramData%\W11PostInstall\Runs\<RunId>` с ограниченными ACL. Пользовательские настройки привязаны к SID. Поддерживаются блокировка параллельных запусков, прерывание, возобновление с повторной проверкой состояния и версия схемы журнала. Произвольные команды из JSON не исполняются.

Отчёт: человекочитаемый TXT/Markdown и структурированный JSON. Телеметрии проекта нет. Перед публикацией логов исключаются имя пользователя, имя ПК и пользовательские пути; установка программ всё равно обращается к соответствующим внешним источникам.

## 12. Проверка качества

1. Статические проверки: синтаксис PS 5.1, PSScriptAnalyzer, схема и связи каталогов, кодировка, отсутствие секретов.
2. Unit: планирование, обнаружение конфликтов, ограничения совместимости, идемпотентность, журнал, ошибки провайдеров и восстановление отсутствовавших параметров.
3. Интеграционные тесты в одноразовых VM: применение → проверка → повторный запуск → восстановление → перезагрузка.
4. Матрица Home/Pro по каждому целевому выпуску x64. Другие редакции/архитектуры получают собственные записи, а не наследуют «проверено» от Pro x64.
5. Сценарии: обычный пользователь/UAC другим аккаунтом; нет сети/WinGet; частичный сбой установки; заблокированная политика; занятый файл; Ctrl+C; аварийное прерывание; pending reboot; конфликт при восстановлении.
6. Приёмка: работают вход в систему, Проводник, сеть, звук, поиск, Store/WinGet, Windows Update, сон и выбранные пользователем функции. Security Center и состояние Defender проверяются согласно выбранному режиму.
7. Для Remover дополнительно: обновление ОС и проверка восстановления из образа. До этого метка «experimental», а не обещание стабильности.

GitHub Actions запускает только безопасные unit/static-проверки на hosted runner. Разрушительные интеграционные тесты выполняются в изолированных VM на выделенной инфраструктуре. Не запускать удаление системных компонентов на рабочем ПК разработчика.

Производительность сравнивать на одном оборудовании/VM, с одинаковыми обновлениями и временем стабилизации: несколько повторов, медиана и разброс; время загрузки, простой CPU/RAM, фоновые процессы, место на диске. FPS/задержки — только при отдельном воспроизводимом игровом тесте. Результат уменьшения RAM сам по себе не доказывает ускорение.

## 13. Этапы реализации и критерии завершения

| Этап | Результат и условие готовности |
|---|---|
| 0. Утверждение | Согласованы этот план, название, видимость GitHub и приоритеты |
| 1. Каркас | PS 5.1 CLI, меню RU/EN, диагностика, каталог, схемы; тесты запуска и обнаружения системы |
| 2. Ядро | Plan/WhatIf/Apply/Verify, журнал, ACL, исходный SID, восстановление; проверен частичный сбой |
| 3. Tweaks | Первые обратимые настройки UI/privacy; применение и возврат на контрольных VM |
| 4. Debloat | Каталог и области удаления; сохранение критических зависимостей; сценарии возврата приложений |
| 5. Apps | Каталог WinGet, обнаружение установленного, лицензии, сбои и перезагрузки; проверка выбранного комплекта |
| 6. Профили | Balanced/Minimal/Gaming/Privacy/Laptop/Custom, экспорт и воспроизводимое применение |
| 7. Defender | Исследование → решение о реализуемых сборках → адаптеры → изолированные тесты; честная матрица Remove |
| 8. Совместимость | Прогон матрицы 21H2–26H2, фиксация исключений по каждой операции |
| 9. Релиз | Документация, CI, ZIP, SHA-256, release notes, лицензия и публикация GitHub |

Ранний preview можно выпустить после этапа 5, явно указав незавершённые функции. v1.0 включает все согласованные модули и опубликованные ограничения; обещание полной поддержки диапазона требует прохождения всей соответствующей матрицы. Сроки оценивать после проверки методов Defender и доступности образов/устройств для тестирования.

## 14. GitHub и распространение

- Предложение: репозиторий `w11-postinstall`, лицензия MIT для собственного кода, README RU/EN.
- До публикации проверить доступный GitHub-аккаунт и наличие репозитория с таким именем; не перезаписывать существующий проект.
- Видимость public/private и аккаунт владельца согласовать перед созданием, если они не заданы к тому моменту.
- SemVer, теги релизов, CHANGELOG, issues для багов/совместимости, шаблон PR и CONTRIBUTING.
- CI: закреплённые версии инструментов и GitHub Actions, анализ PowerShell и каталогов, тесты, сборка ZIP и контрольных сумм.
- Исходный код и пакет релиза доступны для проверки. Контрольная сумма проверяет целостность, но сама по себе не подтверждает издателя; Authenticode добавить при наличии сертификата.
- Сторонние инструменты и установщики не включать в ZIP без проверки лицензий на распространение.

## 15. Границы версии 1.0

Нет GUI, модификации ISO, unattended-установки самой Windows, драйвер-паков, активаторов, очистки пользовательских документов и универсального полного backup-решения. Смена языка/региона и удаление системных защит не выполняются побочно. Полноценное удаление Defender остаётся самостоятельной заявленной функцией с отдельными критериями готовности из раздела 8.
